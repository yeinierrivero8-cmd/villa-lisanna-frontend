BUG #1: URL INCORRECTA EN EMAIL QR (CRÍTICO)
================================================================================

ARCHIVO: backend/app/services/email_service.py
LÍNEA: 104-105
FUNCIÓN: send_admin_notification()

PROBLEMA:
  El QR se genera con URL hacia /api/bookings/{code}/payment-qr
  Esta URL retorna JSON, NO redirige a Stripe
  Cuando se escanea QR → celular muestra JSON (ERROR)

IMPACTO: Admin NO puede cobrar el saldo de reservas

FIX:
  Cambiar línea 104:

  FROM:
  payment_qr_url = f"{BASE_URL}/api/bookings/{code}/payment-qr"

  TO:
  payment_qr_url = f"{BASE_URL}/api/bookings/{code}/balance-checkout"

TIEMPO: 2 minutos

================================================================================
BLOQUEO #1: SMTP TIMEOUT (CRÍTICO)
================================================================================

PROBLEMA:
  Todos los emails fallan: "TimeoutError: timed out"
  Servidor: mail.privateemail.com:465
  Causa: Firewall Hetzner bloquea puerto 465 (anti-spam común)

EMAILS AFECTADOS:
  - Confirmación a cliente
  - Notificación a admin (con QR)
  - Confirmación de pago

IMPACTO: Sistema no puede notificar pagos

SOLUCIÓN RECOMENDADA (Opción 1 - Intentar primero):

  Cambiar .env:
  SMTP_PORT=465  →  SMTP_PORT=587

  Ventajas:
    ✓ Costo: 0
    ✓ Tiempo: 2 min
    ✓ Probabilidad éxito: 70%

  Pasos:
    1. SSH a VPS: ssh -i ~/.ssh/hetzner_key root@188.245.80.35
    2. nano /var/www/villalisanna/.env
    3. Cambiar SMTP_PORT a 587
    4. Guardar (Ctrl+X, Y)
    5. pm2 restart villa-lisanna
    6. Testear con booking nuevo

SOLUCIÓN FALLBACK (Opción 2 - Si puerto 587 falla):

  Usar SendGrid (specializado en email transaccional)

  Cambios .env:
    SMTP_SERVER=smtp.sendgrid.net
    SMTP_PORT=587
    SMTP_USER=apikey
    SMTP_PASSWORD=SG.xxxxxxxxxxxxx

  Ventajas:
    ✓ Muy confiable (99.9% uptime)
    ✓ Free: 100 emails/día
    ✓ Excelente deliverability

  Tiempo: 10 min
  Costo: Gratis
